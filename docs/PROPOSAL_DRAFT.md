# 기획서 본문 초안 — 카닥터 AI

공식 접수양식(DOCX)의 항목 구조는 아직 확인하지 못했다. 아래 본문은 팀의 "기획서 목차·뼈대"(14장) 순서로 썼고, 양식을 받으면 각 칸에 옮겨 붙인다. 5번 항목(개발 계획)은 FAQ에 따라 "구현 범위와 SDK/API 활용"을 적는 곳이므로 10장 내용을 그대로 쓴다. `[확인 필요]`는 출처를 찾아 채워야 하는 수치다.

**한 문장:** 경고등은 고장만 알려주지만, 카닥터 AI는 지금 이 상황에서 무엇을 해야 하는지까지 알려준다.

---

## 1부 왜 하는가

### 1. 기획 배경
차는 점점 똑똑해지는데, 운전자의 판단은 여전히 경고등 기호 하나에 의존한다. Pleos Connect처럼 차량 신호를 앱이 직접 읽을 수 있는 플랫폼이 열렸고, 해외 SDV 해커톤(Eclipse SDV Hackathon 2026 "모든 고장은 흔적을 남긴다")도 차량 진단을 주제로 삼았다.

### 2. 문제 정의
문제는 고장 자체가 아니라, 운전자가 "지금 정비소에 가야 하나?"를 판단할 수 없다는 것이다.
- **의미를 모른다:** 경고등 기호만으로는 어떤 부품이 왜 문제인지 알 수 없다.
- **긴급도를 모른다:** 같은 전조등 고장도 낮에는 급하지 않지만 밤에는 즉시 조치가 필요하다.
- **과잉·과소 대응:** 사소한 고장에 일정을 포기하거나, 위험한 고장을 방치해 사고나 큰 수리비로 이어진다.

### 3. 기존 해결책의 한계
기존 진단 앱과 해외 수상작은 "무엇이 고장났는지"나 "언제 고장날지"까지는 말한다. 하지만 "지금 이 상황에서 무엇을 할지"는 말하지 않는다.

| 사례 | 하는 것 | 하지 않는 것 |
| --- | --- | --- |
| SmartMaintain (SacHacks 2018) | 환경·위치 기반 예측 정비 | 주행 중 상황별 행동 지침 |
| TribalScale (AutoMobility LA 2017) | 사고 심각도 판정 → 출동 연결 | 사고 전 고장의 단계별 판단 |
| Wake Me App (Ford SYNC) | 졸음 감지 시 알림 강도를 단계적으로 높임 | 차량 고장 진단 |
| **카닥터 AI** | 차량 신호 + 날씨·낮밤·속도·남은 거리 → 4단계 행동, 근거 공개, 내비·음성·리포트 연결 | — |

### 4. 목적과 목표
고장 정보를 상황에 맞는 행동 지침으로 바꾼다.
- 판정 대상: 경고등·센서 기반 고장 24종 (v1 구현 완료)
- 시연 시나리오: 6개 (낮/밤 전조등, 빗길 고속 타이어, 정차 상세, 예측 정비, 브레이크 즉시 정차)
- 판정 응답 목표: 신호 변화 후 1초 안에 화면·음성 반영. 규칙 엔진은 기기 안에서 계산하고 네트워크가 필요 없다. [에뮬레이터에서 측정 필요]

**1부 → 2부 연결:** 이 빈칸을 채우기 위해, 우리는 다음과 같은 서비스를 만든다.

## 2부 무엇을 하는가

### 5. 서비스 컨셉
보여주고, 설명하고, 판단하고, 행동을 제안한다.
1. **보여준다:** 차량 그림 위에 문제 부위를 색으로 표시한다(정상 회색 / 주의 노랑 / 위험 빨강 / 4등급 깜빡임).
2. **설명한다:** 원인·위험·할 일을 쉬운 말 3줄로 알려준다(AI, 실패 시 기본 문구).
3. **판단한다:** 부품 심각도 + 환경 가중치로 4단계 등급을 정하고, 근거를 칩으로 보여준다.
4. **행동을 제안한다:** 정비소를 차량 내비 목적지로 보내거나, 긴급출동을 연결하거나, 리포트를 넘긴다.

### 6. 핵심 기능
모든 기능은 "지금 정비소에 가야 하나?"라는 하나의 질문에 답하기 위해 있다.

| 질문에 답하는 단계 | 기능 |
| --- | --- |
| 무엇이 문제인가 | 자가진단(계기판 경고등·공기압·오일류·워셔액), 전체 점검 |
| 어디가 문제인가 | 차량 상단뷰 부위 표시 |
| 얼마나 급한가 | 심각도 × 환경 판정, 판정 근거 공개, 반복 고장 표시 |
| 무엇을 해야 하나 | 4단계 권고, 정비소 내비 안내, 긴급출동 연결 |
| 운전 중에는 어떻게 | 단계적 음성 경고, 음성 질문("지금 가야 돼?"), 주행 중 요약 화면 |
| 정비소에서는 | 정비소 사전 리포트(QR) |
| 고장 전에는 | 예측 정비(공기압 추이 → "약 N일 뒤 경고 기준") |

### 7. 판단 로직
같은 고장도 상황이 바뀌면 답이 바뀌고, 앱은 그 이유를 보여준다.

긴급도 = 기본 심각도(1~3) + 환경 가중치 합(0~3). 6 이상이면 4등급, 4~5는 3등급, 2~3은 2등급, 1은 1등급이다. 브레이크·냉각·조향처럼 기본 심각도 3인 부품은 항상 3등급 이상이다.

| 환경 | 대상 | 가중치 |
| --- | --- | --- |
| 야간 | 등화 | +3 |
| 비·눈 | 와이퍼·워셔액, 제동 | +3 |
| 비·눈 | 타이어 | +2 |
| 고속(80km/h 이상) | 타이어·제동·조향 | +1 |
| 목적지 50km 이상 | 배터리 +2 / 냉각·엔진 +1 | |

등급은 규칙 엔진이 정하고 AI는 문장만 쓴다. AI가 안전 판단을 바꾸지 못하게 하려는 설계다. 판정표는 단위 테스트 16개로 고정했다.

### 8. 사용자 시나리오와 화면
운전자는 화면 하나로 3초 안에 차 상태와 할 일을 안다. (`docs/renders/` 화면 이미지와 `docs/DEMO_SCRIPT.md` 참고)
- A 낮·전조등 → 1등급 주말 방문
- B 같은 고장, 밤 → 3등급 즉시 정비 + 음성 경고 + 정비소 안내
- C 빗길 고속·타이어 → 3등급(비 +2, 고속 +1), 정차하면 상세 설명
- D 공기압이 서서히 빠짐 → 고장 전에 "약 8일 뒤" 예측

### 9. 차별화
실차 신호, 상황 인지, 판단 근거 공개, 차량 내 행동 연결을 한 번에 갖춘 사례는 조사 범위에서 찾지 못했다.
- **차량 안에서만 가능:** 경고등·공기압(Vehicle), 주행/정차(기어), 위치(FusedLocation), 내비(NaviHelper), 음성(TTS/STT)을 하나의 판단으로 묶는다. 폰 앱으로는 같은 답을 줄 수 없다.
- **설명 가능한 판단:** 등급마다 근거 칩(예: "야간 운행 +3")을 보여준다.
- **운전 중 안전 UX:** 주행 중에는 요약과 버튼 하나, 음성 질문만 허용한다.

## 3부 어떻게 하는가

### 10. 시스템 구성과 기술 (접수양식 5번 "개발 계획")
- **플랫폼:** Pleos Connect(AAOS), Kotlin + Jetpack Compose, minSdk 28 / targetSdk 35
- **Pleos SDK 5종 모두 사용**

| SDK | 용도 |
| --- | --- |
| Vehicle 2.3.2 | Safety 경고등(telltale), 타이어 공기압·저압 기준, 엔진오일·브레이크액 레벨, 워셔액, 기어 |
| NaviHelper 3.0.5 | 정비소 목적지 설정, 목적지까지 남은 거리 |
| TextToSpeech 3.3.1 | 단계적 음성 경고, 음성 답변 |
| SpeechToText 3.3.1 | 음성 질문 |
| FusedLocation 1.1.3 | 위치 → 날씨·일출일몰·주변 정비소 |

- **외부 API:** Open-Meteo 날씨(키 불필요), Claude API(설명 문장 생성, 실패 시 기본 문구)
- **검증:** 자동 테스트 69개(판정표, 일출·일몰, 예측, 이력, 음성 명령·경고 정책, 리포트, 정비소 검색 파싱, ViewModel 통합 흐름, 화면 렌더). 화면 12장은 Robolectric으로 렌더해 확인했다. 개발 산출물은 GitHub 소스와 release APK로 낸다.

### 13. 사업성 (심사 항목)
- **타깃:** 차를 잘 모르는 운전자, 출퇴근·장거리 운전자, 업무용 운전자(택시·배달 — 운행 중단이 곧 수입 손실).
- **사용자 확보:** Pleos App Market 기본 추천 앱 제휴, 신차 출고 시 사전 설치 제안. [국내 Pleos Connect 탑재 차량 대수 확인 필요]
- **지속 이용:** 고장이 없을 때도 예측 정비와 이력으로 다시 열 이유를 준다. 지표는 월간 사용자 대비 예측 알림 확인율과 리포트 전송 수로 잡는다. [목표 수치 확인 필요]
- **수익 모델(안):**
  - 정비소 사전 리포트를 통한 견적·예약 중개 수수료
  - 제휴 정비 네트워크(예: 블루핸즈) 연계 시 예약 전환 수수료
  - 업무용 플릿 대상 유료 구독(차량별 예측 정비 리포트)
- **확장:** 같은 판단 구조 위에 외관 손상 스캔(E), 운전자 피로 결합(F), 업무용 운전자 모드(D)를 얹는다.

### 14. 기대효과
- **운전자:** 위험한 고장을 방치하지 않고, 사소한 고장에 일정을 포기하지 않는다.
- **정비소:** 방문 전에 정확한 부위·신호 기록을 받아 진단 시간을 줄인다.
- **제조사:** 고장 대응 경험이 좋아져 고객 신뢰가 오르고, 정비 네트워크로 고객이 연결된다.
- [정량 지표: 불필요한 방문 감소율, 위험 방치 감소 — 측정 방법 정의 필요]

**마무리:** 이제 운전자는 경고등을 보고 무엇을 해야 할지 안다.
