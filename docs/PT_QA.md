# PT 예상 질문과 답변 (12/3~4 대비 초안)

설명회에서 "2차 PT 기술 Q&A 때 전체 구조와 로직을 직접 설명할 수 있어야 한다"고 했다. 아래 답은 코드 위치까지 짚을 수 있게 정리했다.

## 차량 특화성

**Q. 폰 앱으로도 되는 것 아닌가요?**
안 됩니다. 판단에 쓰는 신호는 모두 차 안에서만 나옵니다.
- 계기판 경고등, 바퀴별 공기압, 기어(주행/정차)는 Vehicle SDK에서 옵니다.
- 위치는 FusedLocation SDK에서 받습니다.
- 행동도 차 안에서 끝납니다. 정비소는 NaviHelper로 차량 내비 목적지가 되고, 음성은 TTS/STT로 처리합니다.
- 주행 중에는 화면을 요약과 버튼 하나로 줄여 운전 방해를 막습니다.

**Q. 주행 중 사용은 안전한가요?**
세 가지 장치가 있습니다.
- 기어로 주행 여부를 판단해, 주행 중에는 상세 설명·이력·리포트를 막습니다.
- 질문은 음성으로만 받습니다.
- 음성 경고는 3등급 이상에서만 냅니다. 같은 상태면 반복하지 않고, 등급이 내려가면 한 번 알려줍니다(`engine/AlertPolicy.kt`).

## 창의성

**Q. 기존 진단 앱과 무엇이 다른가요?**
기존 앱은 "무엇이 고장났는지"까지 말합니다. 우리는 "지금 이 상황에서 무엇을 할지"를 4단계로 답합니다.
- 같은 전조등 고장이 낮에는 1등급, 밤에는 3등급입니다.
- 왜 그 등급인지 근거 칩으로 보여줍니다(예: "야간 운행 +3").

**Q. 예측 정비는 어떻게 하나요?**
공기압 샘플을 10분 간격으로 저장합니다. 최근 추이를 최소제곱 직선으로 근사해 경고 기준에 닿는 날을 계산합니다. 오탐을 막는 조건이 있습니다.
- 샘플이 4개 이상이어야 합니다.
- 샘플이 6시간 이상에 걸쳐 있어야 합니다.
- 결과가 14일 이내일 때만 보여줍니다.

ML 대신 설명 가능한 방법을 골랐습니다(`engine/TrendPredictor.kt`).

## 기술 활용성

**Q. SDK를 어디에 썼나요?**
공개 SDK 5종을 모두 썼고, 각각 핵심 기능 하나씩에 연결됩니다.

| SDK | 연결된 기능 |
| --- | --- |
| Vehicle | 진단(경고등 telltale, 공기압, 오일류, 워셔액, 기어) |
| NaviHelper | 정비소 안내, 남은 거리 가중치 |
| TextToSpeech | 단계적 음성 경고와 답변 |
| SpeechToText | "지금 가야 돼?" 음성 질문 |
| FusedLocation | 날씨·일출일몰·주변 정비소 |

**Q. 에뮬레이터에서 고장은 어떻게 재현했나요?**
두 가지를 씁니다.
- 실제 신호는 버추얼 콘솔로 바꿉니다.
- SDK에 없는 신호(전구 한 개 고장 등)는 앱 안 데모 패널에서 주입합니다.

데모 고장은 이력에 기록하지 않고, 리포트에 [데모]로 표시해 실제 신호와 구분합니다.

**Q. AI는 어디에 쓰고, 틀리면 어떻게 하나요?**
등급은 규칙 엔진만 정합니다(`engine/RuleEngine.kt`, 판정표 단위 테스트 16개).
- Claude는 이미 정해진 등급과 근거를 받아 원인·위험·할 일 3줄만 씁니다.
- 프롬프트에 "등급과 권장 행동을 바꾸지 말라"고 명시했습니다.
- 응답 형식이 어긋나거나, 거절하거나, 네트워크가 끊기면 부품별 기본 문구로 대체합니다.

**Q. 테스트는 어떻게 했나요?**
자동 테스트 69개를 돌렸습니다. 단위 테스트, ViewModel 통합 스모크 테스트(Pleos 서비스가 없는 환경에서 데모 흐름 전체), 화면 렌더가 모두 포함됩니다. 화면 12장은 Robolectric으로 렌더링해 확인했습니다(`docs/renders/`).

## 사업성

**Q. 누가, 왜 계속 쓰나요?**
- **타깃:** 차를 잘 모르는 운전자, 장거리·출퇴근 운전자, 업무용 운전자(운행 중단이 곧 수입 손실).
- **계속 쓰는 이유:** 고장이 없을 때도 예측 정비와 이력이 있어서 다시 엽니다.
- **수익:** 정비소 사전 리포트를 매개로 한 견적·예약 중개와, 플릿 대상 구독입니다.

**Q. 정비소 데이터는 실제인가요?**
실제 데이터입니다. NaviHelper에는 POI 검색 API가 없어서 OpenStreetMap(Overpass API, 키 불필요)으로 반경 5km를 검색하고, 그 좌표를 `RouteInfo`로 넘겨 차량 내비 목적지로 씁니다(`data/ShopSearch.kt`). 결과가 없으면 예시 목록으로 대체하고 화면에 "예시 데이터"로 표시합니다. 국내 수록률 보강을 위해 제휴 정비 네트워크 데이터 연동을 검토하고 있습니다.

## 남은 리스크 (솔직하게 말할 것)

- 실제 Pleos 에뮬레이터에서의 연동 검증은 PT 전까지 해야 합니다. 1차 제출 시점에는 단위·렌더 테스트까지 마쳤습니다.
- 긴급출동 번호는 공식 번호로 확인한 뒤 넣어야 합니다.
- APK가 76MB로 큽니다(Anthropic SDK 의존성). 서버 프록시로 옮기면 줄어듭니다.
